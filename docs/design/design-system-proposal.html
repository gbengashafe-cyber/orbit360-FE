Principles

Five rules the whole system follows

Quiet by default

White and grey do most of the work. Borders separate things; shadows only lift things that float, such as menus and dialogs.

One accent, used on purpose

Orbit blue marks the one primary action, the active page and links. If everything is blue, nothing is.

Icons earn their place

An icon stays only if it helps someone find or recognise something faster. Decoration goes.

One status language

Every request in every module uses the same five status colours and the same plain-English labels.

Dense, readable data

HR work is tables and forms. 14px text, compact rows, right-aligned money in tabular figures.

Colour

Brand blue, cool neutrals, five status tones

The blue is taken from the Orbit 360 logo. The greys lean slightly blue so they sit with it instead of looking flat. The logo's indigo is kept for the logo and charts only.

colour for meaning

colour as decoration

  • Gradients on buttons, headers or cards
  • A different colour per stat card or per module
  • Raw hex values or Tailwind colours like purple-500 in pages

Icons

Keep about a third, remove the rest

Today 73 files use icons, about 390 times, including 24 gradient icon tiles beside page titles. One icon set (lucide), one size (16px, 18px in the sidebar), 1.75 stroke.

icons here

  • Sidebar navigation items
  • Icon-only buttons (refresh, close, more actions), with a label for screen readers
  • Alerts and toasts, to show their tone
  • Inputs where the icon is the meaning (search, calendar)

icons here

  • Beside page titles, including the coloured tiles
  • On card and section titles
  • On text buttons ("Initiate new request" doesn't need a plus)
  • On form labels and stat cards

New shared components

PageHeader, StatusBadge, DataTable shell (loading, empty, error, pagination), EmptyState, StatCard, FormSection, ConfirmDialog, DatePicker / DateRangePicker, formatDate, in src/components/system/. Select, DropdownMenu, Dialog, Sheet, Popover and the Sonner toaster are restyled shadcn components; the custom NotificationBar is removed.

Guard rails

An ESLint rule flags bg-gradient-*, raw hex colours, shadow-lg/xl/2xl and palette colours like purple-500 in pages, so new work (from people or Codex) can't drift back.

Reference

A short DESIGN.md and a dev-only /design-system page that renders every token and component from the real code.

Decisions · agreed

Agreed decisions

1

Brand blue #1A66E3

Taken from the logo.

2

Inter as the interface font

Neutral and very legible for tables and figures. The logo wordmark stays as it is.

3

Compact density

36px buttons and inputs, 40px table rows, 14px body text.

4

Status map and labels

The five tones and labels above: "Active" loans as info, "Paid off" as success.

5

Icon policy

Keep icons only in navigation, icon-only buttons, alerts and meaningful inputs.

6

Dates read "02 Dec 2026"

Two-digit day, short month, full year in tables, lists, pickers, dialogs and toasts. Ranges as "01 Dec 2026 – 28 Feb 2027"; with time, "02 Dec 2026, 14:30". Always Africa/Lagos. Exception: notification messages keep the approved copy with DD/MM/YYYY ("submitted on 02/12/2026").

7

Light theme only for now

Tokens are structured so dark mode can be added later without touching pages.
